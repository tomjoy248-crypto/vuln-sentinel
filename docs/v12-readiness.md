## 报告承诺口径

每次扫描报告应优先展示：已抓取页面数、发现的接口/脚本数、实际测试参数数、执行的检测类型、超时/阻断请求数，以及明确的未覆盖项。只有带有请求与响应证据的结果才标记为“已验证”；规则推断结果标记为“建议复核”。

以下项目不能通过仓库代码单独“模拟完成”，必须提供对应资源后执行验收：

| 项目 | 必需资源 | 完成证据 |
| --- | --- | --- |
| Windows 签名 | Authenticode 证书、私钥密码 | 签名验证与 SmartScreen 结果 |
| 支付回调 | 支付宝/微信沙箱商户与公钥 | 真实回调签名验签日志 |
| 密钥托管 | Vault 或 AWS 最小权限账号 | 读取、轮换、失效测试 |
| 登录态/WAF 回归 | 授权测试站点、测试账号 | 请求/响应及误报漏报记录 |
| 多角色 IDOR | 至少两个用户和一个管理员 | 访问矩阵测试报告 |
| 压测 | PostgreSQL、Redis 多实例 | 并发、故障恢复、取消任务报告 |

在这些资源到位前，发布说明应将对应能力标记为“待真实环境验收”，不得标记为已完成。
