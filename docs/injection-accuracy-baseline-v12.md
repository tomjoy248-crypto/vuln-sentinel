# V12.0.2 注入与高风险输入能力基准

## 离线规则基准

`tests/test_injection_accuracy_baseline.py` 覆盖 SQL 注入、反射型 XSS、SSTI、命令注入；正负样本矩阵结果为 TP=4、FP=0、TN=4、FN=0。

`tests/test_extended_injection_accuracy_baseline.py` 增加 XXE、反序列化和文件上传入口的离线正负样本契约。这些结果只衡量规则对受控响应的表现，不代表互联网真实漏洞率，也不证明目标可被利用。

## 自动检测与人工复核边界

| 能力 | 自动检测能说明什么 | 需要人工复核什么 |
|---|---|---|
| SQL 注入 | 数据库错误、响应差异或时间探针等线索 | WAF、软 404、业务差异及真实数据影响 |
| 反射型 XSS | payload 反射和响应上下文线索 | 浏览器 DOM 执行、编码上下文、CSP 与可利用性 |
| SSTI | 模板表达式计算或解析错误线索 | 模板引擎类型、真实执行影响 |
| 命令注入 | 命令输出/错误特征；不执行破坏性命令 | 真实命令执行影响与环境边界 |
| XXE | XML/DTD 受控探针反射或解析错误 | 外部实体读取、出站请求和解析器配置 |
| 反序列化 | 响应头、Cookie 或页面中的已知序列化特征 | 是否存在可达的危险反序列化路径或 gadget chain |
| 文件上传 | 上传表单/端点、测试文件被接受的线索 | MIME 绕过、存储位置、执行权限、鉴权和路径穿越 |

另需人工验证登录态、IDOR/越权、复杂业务流程，以及 WAF/CDN、软 404、缓存和限流对结果的影响。自动结果必须保留请求/响应证据，并按“已验证、建议复核、待人工复核”区分；上传入口或序列化特征本身不得直接宣称已确认 RCE。

## 真实靶场验收

若要把 TP/FN/FP 作为产品准确率或发布验收数据，需在自有或书面授权靶场准备正例、负例、边界例和 WAF/软 404 场景，保存请求、响应、软件版本及人工复核结论。当前离线基准不能替代该验收。
